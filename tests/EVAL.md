# Skill evaluation

Each fixture is a synthetic, noisy GitHub Actions log (300–750 lines, with timestamps, ANSI codes, group markers and progress output) reproducing one real-world failure class. For each one, the expected **category**, **root cause** and **fix** are recorded in [`fixtures/expected.json`](fixtures/expected.json) (generated by [`fixtures/generate_fixtures.py`](fixtures/generate_fixtures.py)).

The evaluation has two parts:

1. **Automated pipeline check** (`python3 tests/run_eval.py`): clean → detect → match → categorise. A fixture passes when the top-ranked known pattern and the category are the expected ones *and* the root-cause line survives in the digest. CI enforces ≥ 9/10.
2. **Agent-run review:** the full skill process (`ci_doctor.py` brief → diagnostic method → report template) was run by Claude on every fixture. The resulting diagnosis was compared with the expected root cause and fix.

## Limitations of this evaluation

- The fixtures and the signatures were written by the same author, so this eval measures that the pipeline works end to end and stays correct as code changes (a regression gate). It isn't an independent accuracy benchmark. Real-world accuracy will be lower, especially for failures no entry covers. In that case the skill falls back to the diagnostic method, and the "If this isn't it" section matters more.
- `fetch_failed_logs.py` is tested against a fake `gh` executable that mimics real `gh` JSON. Run it against a live repository before relying on it in automation.
- Next steps to strengthen the eval: add anonymised real-world logs contributed by users, measure top-3 accuracy on them, and track misses as new pattern entries.
